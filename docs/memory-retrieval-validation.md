# 本地记忆检索的合成核查记录

本记录说明模型选型和当前检索管线的实际核查结果。数据全部为构造的学习问题与记忆片段，没有读取个人聊天数据库，也没有调用回答模型 API。这里记录的是少量工程检查，不是公开基准测试，不能据此推导生产召回率、准确率或真实回答质量。

## 固定模型与运行条件

| 用途 | 模型与固定 revision | 当前模型卡许可证 | 权重文件大小 |
| --- | --- | --- | --- |
| 向量召回 | [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small/tree/614241f622f53c4eeff9890bdc4f31cfecc418b3)，`614241f622f53c4eeff9890bdc4f31cfecc418b3` | MIT | 470,641,600 字节 |
| 语义重排 | [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3/tree/953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e)，`953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e` | Apache-2.0 | 2,271,071,852 字节 |

许可证以对应模型仓库的当前 metadata 为依据；BGE 这一具体模型是 Apache-2.0，不能沿用其他 BGE 模型的许可证描述。两份 safetensors 合计约 **2.553 GiB**，此外还有分词器、配置与 Python 运行依赖。普通准备只下载这些必要文件，不下载同模型的 PyTorch BIN、ONNX 或 OpenVINO 副本。

本机为 Apple M3、macOS arm64、Python 3.11.15；此次环境使用 SentenceTransformers 5.7.0、Transformers 4.57.6、PyTorch 2.14.0。两模型均在 CPU 上运行，PyTorch 计算线程为 2。E5 使用 `query:` / `passage:` 前缀，产生归一化的 384 维向量。BGE 返回对原始 logit 做 sigmoid 后的分数；该数值没有经过本产品的概率校准。

## 组件选型观察：6 个构造场景

原始文件：[memory-retrieval-component-selection.json](evidence/memory-retrieval-component-selection.json)。文件保留每个问题、候选原文、预期相关条目的索引、向量相似度与 BGE 原始分数。前三例把正确事实放在较早位置，后面添加了 10 条更新的干扰记忆，用于检查不能先截取最新 8 条再检索。

在先前候选模型 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` 的检查中，中文过拟合问题还会保留“学习率控制更新步长”这一干扰项。换为 BGE 后，相同问题与文本的相关项分数为 `.010020`，学习率条目为 `.001270`，按最高分的 `.2` 做相对截断后只保留正确项。旧候选模型给这两个文本的分数分别为 `.010676` 与 `.005752`。这只是选型过程中的具体观察，不是维护两套产品或公布模型整体优劣排名。

BGE 对两个明显无关文本也给出了更低分数：

| 问题与无关文本 | 先前候选模型分数 | BGE 分数 |
| --- | ---: | ---: |
| 问何时可撤销已提交订单；文本只讲设置头像和语言 | .004312 | .000037 |
| 问 Mac 本地运行与私密文本是否外传；文本只讲梯度下降优化参数 | .002523 | .000044 |

两轮检查之间词面泛词规则也有更新，因此上表只比较相同问题–文本对的模型分数，不将前后整条管线的输出当作严格 A/B 实验。BGE 组件原始文件仍保留了没有绝对下限时的结果：唯一的头像候选会通过相对截断。这个现象正说明**相对第一名的阈值本身不能处理“全部候选都无关”**。

## 最终管线核查：真实模型与临时 SQLite

原始文件：[memory-retrieval-final-pipeline.jsonl](evidence/memory-retrieval-final-pipeline.jsonl)。本轮使用已切换的真实默认模型，将构造事实写入临时 SQLite，再实际调用 `retrieve_memory`，没有使用模型替身。配置为：向量候选最低相似度 `.82`、重排极低分下限 `.0001`、相对最高分截断 `.2`，其余使用当前默认值；未为单个场景更改参数。

| 构造场景 | 预期 | 本轮实际输出 |
| --- | --- | --- |
| 中文：训练集好、测试集差，旧记忆讲过拟合 | 找回旧过拟合事实 | 仅该事实 |
| 英文：熟悉样本好、新样本差，用同义表达追问 | 找回旧过拟合事实 | 仅该事实 |
| 中文：随机关闭神经元缓解记住训练样本 | 找回旧 Dropout 事实 | 仅该事实 |
| 问富士山海拔，候选只有 ML、数据库和算法 | 空 | 空 |
| 问撤销订单，唯一候选只有头像设置 | 空 | 空 |
| 问 Mac 离线与隐私，候选只有统计模型、梯度下降、缺失值 | 空 | 空 |

这说明这六个构造场景按预期工作，不能包装成召回率指标。JSONL 的 `selected` 是最终真实输出；`simulated_relative_0.2` 是刻意忽略绝对下限的诊断性计算，用于展示仅做相对截断的局限。文件中的每例总耗时还包含临时数据准备、原始分数采样和真实检索调用，不代表单次用户请求延迟。

## 额外 8 个独立构造例与保留反例

原始文件：[memory-retrieval-independent-examples.json](evidence/memory-retrieval-independent-examples.json)。这些问题在首轮六例之后单独构造，未用于选择首轮样例或逐项调整阈值，仍不属于统计意义上的独立测试集。

| 问题–文本类型 | 人工预期 | BGE sigmoid 分数 |
| --- | --- | ---: |
| 中文瞬时变化率问题 → 导数定义 | 相关 | .614253 |
| 英文“每次排除一半候选” → 二分查找解释 | 相关 | .000748 |
| 中文矩阵乘法条件 → 维度约束 | 相关 | .222227 |
| 英文参数优化问题 → 中文梯度下降事实 | 相关 | .711706 |
| 英文训练好、未见数据差 → 少词面重合的过拟合解释 | 相关 | .000267 |
| 中文如何确认工具写入成功 → 实查记录和幂等状态说明 | 相关 | .211650 |
| 问二分查找为何要求有序 → 只说可用 Python 编写 | 信息不足，不能回答所问条件 | **.002626** |
| 问删除银行卡与取消自动扣费 → 只说头像大小和主题颜色 | 无关 | .000027 |

保留第七例是为了明确边界：**同一主题下的弱相关信息可能比真正的同义答案得分更高**。当前 `.0001` 的极低分过滤不会移除这个信息不足的候选。提高统一阈值则可能先删掉正确英文同义材料，不能通过把阈值调高就宣称解决了问题。

因此，`.82` 与 `.0001` 都是当前工程配置，不是经过概率校准的置信度门槛；`.2` 用于相对降噪。向量检索与重排都不验证事实真假，不解决记忆过时或冲突，也不证明一段材料足以回答当前问题。后续需要基于更多真实任务的人工标注来评估取舍，而不是反复迎合这几个样例。

## 本机开销与可复核范围

- 组件检查用 BGE 单独对 11 对问题–文本评分，batch size 为 4：首次约 **1.787 秒**，后续两组约 **.425 秒、.478 秒**；单候选约 **.074 秒**。这是本机短文本的单次观察，不是稳定延迟承诺。当前产品运行时的重排 batch size 为 8，长文本和更多候选会改变开销。
- 在已有模型缓存的情况下，`prepare_retrieval.py --smoke` 整个进程约 **7.89 秒**；其中包含 Python 导入、准备、加载及两个真实中英文例子的推理，不能当作每轮聊天耗时。`/usr/bin/time -l` 记录的最大驻留内存为 **2,252,603,392 字节，约 2.10 GiB**。这是单次进程观察，不是内存上限；操作系统分页、文本长度、批量大小和同时运行的服务都会影响占用。
- BGE safetensors 本身约 **2.115 GiB**，与 E5 合计约 **2.553 GiB**。磁盘权重大小与运行时驻留内存是不同指标；内存紧张时可以使用 `MEMORY_RETRIEVAL_MODE=lexical`。
- 实际默认双模型的两例 smoke 已通过：中英文相关文本都分别高于无关文本，E5 维度为 384 且归一化。状态为 `ready`。这只验证本地模型能工作，不等同于整套 Agent 回答质量评测。

重新检查本机安装和双模型推理：

```sh
MEMORY_RETRIEVAL_MODE=hybrid uv run python scripts/prepare_retrieval.py --smoke
```

该命令会在显式准备时下载缺失的公开权重。普通启动只后台加载已有缓存，普通检索不下载模型；语义模型不可用时保留词面检索降级。上述 JSON 中的输入均为可公开的合成文本，后续复核检索输出应继续使用临时 SQLite，避免连接个人聊天库。
