# LearningTree v0.2.0

LearningTree now offers optional semantic learning-memory retrieval and a lighter first installation. The README includes a screenshot and short interaction demo made with synthetic content.

## What's new

- **Memory tied to the active learning path:** filter source nodes first, then combine BM25 keywords and optional multilingual E5 vectors with reciprocal rank fusion. Optional BGE reranking, deduplication and complete-entry budgets select memories with source references. Preferences use a separate budget; sibling facts do not silently enter the answer.
- **Basic setup without model downloads:** PyTorch, Transformers and local weights are optional. `setup --with-retrieval` adds them explicitly; a failure in that optional stage leaves the basic installation usable. Settings distinguishes missing dependencies from models that need preparation.
- **A visible, no-key introduction:** synthetic screenshots and an offline interaction recording show branches and source return. The first-run guide starts with the separate demo workspace. The demo uses fixed replies, not a real AI model or an answer-quality benchmark.
- **Question-based branch titles:** first questions receive bounded background title suggestions, with fallback labels and preserved custom/imported titles.

## Try it

Install uv and Node.js 24 LTS (22.12+ supported), then run:

```sh
git clone --branch v0.2.0 https://github.com/Yuyang16Z/learning-tree.git
cd learning-tree
uv run python scripts/manage.py setup
uv run python scripts/manage.py dev
```

Open **http://127.0.0.1:5174** for the offline demo. Stop it with Ctrl+C, then run `uv run python scripts/manage.py start --open` for your personal workspace at **http://127.0.0.1:8099**. Add your answer-model endpoint, model ID and API key in Settings. The two workspaces use separate databases.

Optional semantic memory:

```sh
uv run python scripts/manage.py retrieval
```

This installs the optional dependencies and prepares pinned **E5-small + BGE-reranker-v2-m3** weights, approximately **2.55 GiB**, plus tokenizers and Python dependencies. Inference also requires RAM; there is no extra retrieval API key. Restart afterward. If `.env` explicitly sets `MEMORY_RETRIEVAL_MODE=lexical`, change it to `hybrid` to enable semantic retrieval. Preparation does not rewrite that preference. Normal startup never downloads weights, and chat plus keyword retrieval remain usable if the optional components are unavailable.

## Upgrade and data compatibility

1. Finish active answers and stop the app.
2. Before updating, run `uv run python scripts/manage.py backup` and retain the private backup.
3. Update the checkout, then run `uv run python scripts/manage.py setup`. Existing optional dependencies and cached weights are retained by this command.
4. Run `uv run python scripts/manage.py start --open` and refresh the browser.

Existing chat, configuration, node and memory records keep their IDs and content. The additive `MemoryEmbedding` table is a rebuildable cache; missing vectors are created lazily. Export/import retains the existing version-1 format. Database backups do not cover browser drafts, MCP memory or learning files; preserve those separately when moving machines.

## Scope and verification

LearningTree remains a **local, single-user application** bound to loopback, without account authentication. Model keys stay in the local SQLite database and are not encrypted at rest. MCP tools can run local programs. Local retrieval avoids a separate retrieval service, but selected memory still accompanies prompts sent to your configured answer model. Relevance ranking does not verify facts, resolve conflicting memories or guarantee that a retrieved passage answers the question.

`manage.py check` and `manage.py e2e` exercise isolated synthetic/mock regression cases. After optional installation, `uv run python scripts/prepare_retrieval.py --smoke` checks real local inference with fixed Chinese/English examples. These checks serve different purposes; their passage counts are not model-quality metrics.

See the [README](https://github.com/Yuyang16Z/learning-tree/blob/v0.2.0/README.md), [operation and restore guide](https://github.com/Yuyang16Z/learning-tree/blob/v0.2.0/docs/operations.md), and [model validation with retained counterexamples](https://github.com/Yuyang16Z/learning-tree/blob/v0.2.0/docs/memory-retrieval-validation.md).

## 中文说明

本版加入按当前学习路径限定来源的混合记忆检索，并把语义模型改为可选安装。基础 `setup` 不再安装 PyTorch/Transformers 或下载模型；先运行 `dev` 即可无密钥体验，真实学习使用 `start --open` 并自行配置回答模型。README 新增使用虚构内容制作的截图与短动图，只展示交互。

需要语义检索时运行 `manage.py retrieval`，另需约 **2.55 GiB** 权重、依赖空间和运行内存；失败不会妨碍基础聊天与关键词检索。已有 `.env` 若显式选择 `lexical`，准备模型后仍须改为 `hybrid` 并重启才能启用。

升级前停止应用并执行 `manage.py backup`，更新代码后重新 `setup`、启动并刷新。旧聊天、配置和记忆保持原有 ID 与内容，新增向量表仅为可重建缓存。应用仍限本机单用户使用；检索相关性不代表事实正确，也不等于真实回答质量已得到全面验证。
