# Changelog

## Unreleased

- Add `scripts/evaluate_retrieval.py` to measure, on a temporary copy of your own database, how the character-class estimator compares with the earlier UTF-8 byte count (including how many learning paths would compact with 32,768- and 1,048,576-token windows), what memory retrieval returns for every completed question in the path, other-branch and all-topic scopes, replayed against the facts that existed when it was asked and scored with proxy recall@k and MRR rather than human relevance labels, and whether topic search finds each question's node through text other than the question itself. The original file is never opened for writing, no model is called and nothing is downloaded; the report in `artifacts/` holds ids, counts, scores and timings without paths or conversation text unless `--include-text` is given, `--hybrid` exits with status 2 unless both local models (embedding and reranking) are prepared, at least one question reaches them and no retrieval falls back from either, and `--synthetic` runs a built-in fixture. See [offline retrieval evaluation](docs/retrieval-evaluation.md).
- Recap a branch when returning from it: **Back to source** and **Continue with reflection** now show a dismissible card above the composer at the source with up to four sentences picked from the branch's current answers (corrections, conditions, definitions and open questions first, Markdown markers removed), your reflection and your latest understanding mark. The card says it is a local extract rather than an AI summary; `GET /nodes/{id}/return-summary` reads stored answers only, calls no model and writes nothing. The recap is never stored and closes when you dismiss it, send a question or open another node.
- Open **Not understood** in the learning map header to list this topic's answered questions marked **Not yet**, newest first and up to 30, and jump to one; the badge counts them. The list is computed in the browser from the map, so marks made in any window update it at once.
- Mark how well you understood the open question: once it has an answer, the bar above the conversation offers **Not yet**, **Roughly** and **Can explain** (还没懂 / 大致懂了 / 能讲清楚), inside the source bar beside **Back to source** in a branch and in a bar of its own on the main line, disabled while the question is being answered; choosing the active mark again clears it, and earlier questions on the path are marked by opening them. Map cards take a quiet stripe and tint from their last node's mark, named in the card tooltip, while pending and failed answers keep their glyphs. Marks live in an additive nullable `understanding` column, so existing nodes stay unmarked; they never change answers, titles or context summaries (summary cache keys ignore them), reach other windows through the change feed, and are exported only for marked nodes. Earlier app versions reject backups containing marks; exports of unmarked topics stay importable there.
- Require a phone-access token from other devices. A request whose Host is not a loopback name, or that arrives through a proxy such as Tailscale Serve, needs an `HttpOnly`, `SameSite=Strict` cookie holding a 32-byte random token stored in `.runtime/phone-access-token` (mode 0600); only the app shell, `/health` and pairing answer without it. **Settings → Phone access** on this computer now shows a QR code whose link carries the token in its URL fragment: opening it pairs the phone once, the page swaps the token for the cookie and removes it from the address bar, and **Replace access token** unpairs every device. Opening that panel on this computer creates the token whatever the Tailscale state, and **Open at another address** builds the same pairing QR code and link for a host listed in `ALLOWED_HOSTS` (for example behind a reverse proxy), the host running Docker or Tailscale Serve in front of a container; `ACCESS_TOKEN_FILE` moves the token, which the Docker image keeps in its `/data` volume. An unpaired phone is asked to scan the QR code again; failed pairing attempts are rate-limited. Requests from this computer (desktop window, scripts, Docker's loopback port) need no token, and `ACCESS_TOKEN_MODE=off` disables the check. **A phone set up before this change must scan the new QR code once.**
- Bound the agent's tool rounds by time and by size: after `AGENT_TIME_LIMIT_SECONDS` (default 180) or once the tool results gathered for an answer reach `AGENT_TOOL_TOKEN_BUDGET` estimated tokens (default 60,000), the model stops calling tools and answers from what it has in the existing final round. Budgets are checked between rounds, so a running tool call is never interrupted. The collapsed diagnostics under the answer say which budget ended the tool rounds (`tool_budget_stop`).
- Keep the complete text of every tool call in an answer, up to 2,000,000 characters per call (longer output is cut and flagged), in the new `ToolResult` table. Every tool round, from the first, also offers the model a read-only `read_tool_result` tool bound to that answer (so the tool list, and with it the provider's prompt cache, stays the same between rounds) to page through a result that was cut for it (MCP output still stops at 24,000 characters) or shortened in a later request, and tool steps whose 3,000-character preview is cut offer **View full result** to load the stored text page by page. Stored results belong to their answer: deleting the branch or topic removes them, tree exports omit them (steps keep their previews) and demo answers store none.
- Reuse each MCP server's tool list for 60 seconds instead of listing it before every tool-enabled question. A server that announces a change (`notifications/tools/list_changed`) is listed again on the next question, and **Test connection** always lists afresh, so an upgraded server's tools appear without restarting the app.
- Connect remote MCP servers over Streamable HTTP: **Settings → MCP tools → Add MCP → Remote HTTP** takes a server URL and optional request headers such as `Authorization`. Header values are stored locally and never shown again (only their names are listed; leaving a value blank keeps it), redirects are not followed, and the host must resolve to public addresses unless **Allow private addresses** is checked for a development server on this computer. Connection tests and failed calls report fixed messages instead of raw errors (a URL without an MCP endpoint reads as not found, and a redirect or client error on a new connection is not retried); a call that timed out or lost its connection after it was sent is reported as having an unknown outcome, never as an unreachable server, so the model checks before calling a tool with side effects again. Existing local servers are unchanged; the additive `transport`, `url`, `headers` and `allow_private` columns default to a local command.
- Preload the managed web-research MCP's `web_search` and `read_webpage` (under their `mcp_<id>_` names) in the on-demand tool catalog exactly like the built-in web tools, so a first model round can search or read the web without a discovery call; look-alike names stay searchable only.
- Assemble the system prompt stable-first: fixed rules, the ancestor learning path with notes and imported summaries, then the current node, note, quoted passage, document excerpts and finally retrieved memories. For native Anthropic models, send that stable head as a cached text block with the top-level cache marker when it is at least 1,024 characters and still a prefix of the fitted prompt; a provider that rejects the marker gets one plain retry and the marker is then disabled for that endpoint. OpenAI-compatible requests are unchanged, and cached tokens appear in the answer diagnostics.
- Stream tool rounds: text and visible reasoning the model produces before a tool call now appear as they arrive, tool steps show once the message is complete and its stop reason accepted, and the final answer is relayed as it streams instead of being replayed in small chunks. OpenAI-compatible rounds assemble streamed tool-call fragments by index and parse the arguments only at the end, so partial calls never execute.
- Compact older history once it exceeds `CONTEXT_COMPACTION_RATIO` (default 0.6, `.env`) of the input budget, so follow-ups and tool results keep room; when tools reserve working space the ratio applies to the remaining room. Every request is still fitted to the hard budget, and mandatory input is judged only against it.
- Add **Settings → Models & API keys → add/edit → Advanced → Detect**: ask the provider for the model's context window (Anthropic model information, or `context_length`/`max_model_len`-style extras of an OpenAI-compatible `/models` list), fall back to an approximate built-in catalog for well-known families, fill the field and say which source answered. Detection never runs automatically, nothing is stored until you save, provider errors are reduced to fixed messages, and the defaults stay 32,768 / 4,096. A reported window outside the accepted 8,192–2,097,152 range is named in the note instead of being filled in, the field and **Save** wait while detection runs, starting it clears an earlier form error, and a result that arrives after the API format, URL, model ID or key changed is discarded along with the note.
- Show a collapsed diagnostics block under each answer: estimated versus reported input tokens, cached tokens, tool rounds and elapsed time, with output tokens, compaction state, calibration ratio and per-phase timings inside. The numbers are stored with the message, sent once before the answer ends and excluded from tree exports. Both providers now report usage (OpenAI-compatible streams request the usage chunk, including DeepSeek cache hits, with a one-time fallback when a gateway rejects `stream_options`; Anthropic totals uncached, cache-creation and cache-read input tokens), and real answers with at least 2,000 estimated units teach a clamped per-model calibration ratio kept in the rebuildable `ModelCalibration` table and removed with the model. A ratio above 1 shrinks that model's input budget; ratios below 1 never enlarge it, and demo answers never learn.
- Replace the UTF-8 byte estimator with a character-class token estimator (about 0.7 unit per CJK character, 0.33 per visible ASCII character, 0.1 per whitespace character and 1 per other non-ASCII character, times a 1.15 safety factor), so Chinese conversations keep roughly three times as much original history before compaction and summaries start; tool results are trimmed by characters and re-verified. Summary, extraction and document producers keep their byte budgets with explicit conversion at the boundary. Estimates remain local approximations, not provider token counts.
- Add two switches under **Settings → Memory → Memory retrieval** to widen memory recall to other branches of the same topic and to other learning topics. Settings stays open while a switch is being saved, and a save that conflicts with another window says it is reloading and then that the change was not saved, also after switching Settings tabs. The switches are read again each time the Memory tab is shown, so a read that failed is retried and a change made on another device appears. The current learning path stays always on; widened facts are ranked with path facts but listed after them in their own labelled sections with a smaller budget, and every answer shows a compact **Referenced** line naming the memories it was given, each opening its source node. Entries whose topic or node has since been deleted are struck through and disabled, and an entry deleted after the line was shown is checked when chosen: the app says the source was deleted and keeps the current conversation open instead of switching to an empty workspace. Malformed provenance entries in a stream or a stored answer are skipped, and if a stored answer still cannot be displayed, the conversation area says so and offers **Reload** while the topic list and map stay usable, instead of the whole page going blank. That message keeps the conversation header with the topic title and the learning-tree toggle, so on a phone, where the map starts closed, another question can still be opened from the map.
- Search a topic's history from the learning map: besides instant title and quote matches, the search box lists full-text matches in questions, completed answers, learning notes and facts, labelled with what matched and with a short snippet shown without Markdown markers, and choosing a question or answer hit scrolls to the matching text and highlights it, also inside formatted answers. History hits disappear as soon as the query or topic changes, so a slow or failed search never leaves an earlier query's matches listed, and queries stop at the API's 300-character limit. Until the server answers, a search without instant matches says **Searching…** instead of reporting no results, and the count reads “30+” when the capped list leaves matches out. A SQLite FTS5 index maintained by database triggers backs the search and is rebuilt at start-up when needed; the answer model gets a matching read-only `search_learning_history` tool bound to the same scope switches, shown in tool steps as **Search learning history** (搜索学习记录). The original-text reader `read_learning_source` is now named **Read source passages** (回查原文) so the two are easy to tell apart.
- Store extracted topic facts with a type (definition, condition, correction, open question, learner state or conclusion) and key terms, shown as tags in **Settings → Memory**. A new fact can mark an earlier fact of the same learning path as superseded: it stays listed as **Superseded** until deleted but no longer reaches answers or search. Hand-edited facts are never superseded automatically.

## 0.2.0 — 2026-09-12

- Add source-scoped learning-memory retrieval: BM25 and optional multilingual E5 vectors, reciprocal rank fusion, optional BGE reranking, complete-entry budgets and source annotations. User preferences remain separate; sibling branches do not silently supply facts.
- Preserve existing memories and add a rebuildable embedding cache. Memory, branch and tree deletion also remove associated vectors. Publish synthetic inference observations, including known relevance counterexamples.
- Make semantic dependencies and weights optional. Basic `setup` skips PyTorch/Transformers and model downloads; `retrieval` installs the extra on demand. `setup --with-retrieval` retains the usable basic installation if optional preparation fails.
- Show the difference between missing semantic dependencies and unavailable models in Settings → Memory. Normal startup never downloads weights; keyword retrieval remains available.
- Add a synthetic product screenshot and short offline interaction demo to both READMEs, with a no-key trial path and separate personal workspace instructions.
- Branch labels now summarize the first branch question with the selected model in the background. Empty branches use a localized placeholder, and failed summaries fall back to the question.
- Preserve source anchors and custom/imported titles; repair legacy labels that copied the beginning of a source answer.

See [v0.2.0 release and upgrade notes](docs/releases/v0.2.0.md) for installation, resource costs and compatibility.

## 0.1.0 — 2026-09-11

First public LearningTree release.

- Continuous chat, branches, inline explanations, source return and understanding notes.
- Topic map with turn navigation and reversible centering.
- Durable answers, retries, revisions, drafts and JSON import/export.
- OpenAI-compatible Chat Completions and native Anthropic Messages.
- Optional pinned MCP tools with persistent sessions.
- Chinese and English interface with saved language preference and LearningTree branding.
- Portable setup, development and backup commands, isolated browser tests, dependency locks, CI and MIT licensing.
