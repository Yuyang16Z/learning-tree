# Security policy

LearningTree is a personal application for loopback use on a trusted computer. It is not an authenticated shared service. Public interfaces or tunnels require additional authentication, transport security and isolation.

Model API keys and tool configuration are stored in local SQLite without encryption at rest. Protect the database and backups as credentials. A stored model key is only sent to the protocol and address it was saved with; **Detect** in an edited model form never sends it to a changed address. Tree exports omit model/server configuration but may contain sensitive chat text, images, reasoning and tool results.

Phone access is supported only through a private network such as Tailscale Serve, which limits connections to your signed-in devices; in addition, every request that does not come from this computer must carry the phone-access token (below). Tailscale Funnel, port forwarding and public tunnels would expose the pairing page and an API that can run MCP programs to anyone who obtains that token; **Settings → Phone access** reports Funnel exposure.

## Built-in request protections

These narrow common browser and tool attacks; they do not make the API safe to publish.

- **Host check (DNS rebinding).** Requests must use a loopback host name, a Tailscale Serve name (`*.ts.net`) or a name listed in `ALLOWED_HOSTS` (comma-separated). A page whose domain was rebound to 127.0.0.1 still sends its own Host header and gets `400`.
- **Phone-access token.** A request comes from another device when its Host is not a loopback name or it carries proxy headers (`X-Forwarded-For`, `X-Forwarded-Host`, `Forwarded`, `Tailscale-User-Login`, `Tailscale-Funnel-Request`). Tailscale Serve proxies from this computer, so the peer address cannot decide this; it keeps the client's Host and adds those headers. Such requests need the cookie `lt_access` equal to a 32-byte random token kept in `.runtime/phone-access-token` (file mode 0600, directory 0700; `ACCESS_TOKEN_FILE` moves it, and the Docker image keeps it in its `/data` volume), compared in constant time; only the app shell (`/`, `/assets/*`), `/health` and pairing itself (`POST /phone-access/session`) answer without it. The token is created when **Settings → Phone access** is opened on this computer, whatever the Tailscale state, and travels only in the URL fragment of a pairing link (the Tailscale QR code, or a link the panel builds for another address whose host is a Tailscale name or listed in `ALLOWED_HOSTS`), which browsers never send to a server or put in a `Referer`. Pairing exchanges it once for an `HttpOnly`, `SameSite=Strict`, 400-day cookie, `Secure` over HTTPS and on `*.ts.net`; failed pairing attempts are rate-limited in memory. **Replace access token**, available only on this computer, unpairs every device. Requests from this computer — the desktop window, scripts and Docker's loopback-published port — never need the token. `ACCESS_TOKEN_MODE=off` disables the check.
- **Cross-site writes.** `POST`, `PUT`, `PATCH` and `DELETE` with an `Origin` header must come from a local page (any port) or the same origin. CORS alone only stops a foreign page from reading a response, not from triggering a write. Requests without `Origin`, such as scripts, are still accepted.
- **Fetch tool (SSRF).** The built-in `fetch` tool accepts only `http`/`https` URLs without credentials. Every address the host resolves to must be public — loopback, private, link-local (including cloud metadata), shared CGNAT (including Tailscale) and reserved ranges are refused — and each redirect is checked again, up to five. The request connects to the address that was checked, while HTTPS still verifies the certificate for the original host name. This applies only to the built-in tool; MCP servers, including the web-research preset, make their own requests.
- **Question images.** `/ask` accepts at most four images of up to 4 MiB each, matching the composer.
- **Remote MCP servers (SSRF).** A remote (Streamable HTTP) MCP server needs an `http`/`https` URL without credentials. Before connecting, every address its host resolves to must be public — the same ranges as the fetch tool are refused — unless that server's **Allow private addresses** option is on, which is meant for a development server on this computer. Redirects are never followed. The HTTP client resolves the name again when it connects, so DNS rebinding after the check is not prevented. Header values such as `Authorization` are stored in SQLite like model keys, are never returned by the API or logged, and connection-test errors are reduced to fixed messages.

Local MCP servers are programs whose permissions follow the launching user's OS account. The file preset narrows the exposed library directory but is not a system sandbox. Remote MCP servers receive the tool arguments and content of the calls the model makes to them. Configure only trusted tools and endpoints. Model requests and selected tool calls send relevant content to those services.

## Reporting

Use **Security → Report a vulnerability** in this repository when available. Otherwise open an issue asking for a private channel without exploit details, personal data or credentials. Do not attach real databases or `.env` files.

The current main branch is the supported development version. Back up local data before upgrading older snapshots.
